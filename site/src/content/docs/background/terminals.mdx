---
title: Agent terminals
description: Terminals a v2 agent runs and shows the client, display only.
---

In ACP v2 the agent runs commands itself and may show the client their terminals (`terminal_update`, `terminal_output_chunk`). They are display only: the client cannot type into them. v2 removed v1's client-run terminals.

## On the client

Each change is a `terminal` event; the session keeps every terminal, across turns, because a terminal can outlive the turn that started it and its updates can arrive before the tool call that shows it.

```ts
for await (const event of turn) {
  if (event.type === 'terminal') {
    if (event.replaced) redraw(event.terminal.id, event.terminal.output); // a snapshot replaced the output
    else if (event.appended) append(event.terminal.id, event.appended);    // new bytes
  }
}
const terminal = session.terminals.get(terminalId); // { command, cwd, size, output, exitStatus, cancellable }
```

A tool call shows a terminal with content `{ type: 'terminal', terminalId }`. Output is bytes, kept up to 1 MB per terminal; a chunk may split a UTF-8 character or an escape sequence. `terminalText(terminal)` decodes the whole output for a transcript.

## On the agent

`turn.showTerminal({ command, cwd, size, cancellable })` returns a handle with `write(data)`, `replace(data)`, `exit({ exitCode, signal })`, `detach()` and `signal`. See [Background work](../background-work/) for an example.
