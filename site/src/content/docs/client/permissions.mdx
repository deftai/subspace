Agents ask before acting (`session/request_permission`). The client option `permissions` decides. The default is `'reject'`: nothing is allowed unless you say so.

## Ready-made rules

Most programs need one of a few answers, so they come ready-made:

<Tabs syncKey="language">
<TabItem label="TypeScript">

```ts
import { allow, allowInside, firstOf, readOnly, reject } from '@deft-subspace/acp';
import { askInTerminal } from '@deft-subspace/acp/node';

start('claude', { onPermission: readOnly });                                   // reads and searches yes, the rest no
start('claude', { onPermission: firstOf(allowInside(repo), askInTerminal()) }); // edits inside the repo yes, ask about the rest
start('claude', {
  onPermission: firstOf(reject({ commands: /rm -rf|git push/ }), allow({ kinds: ['read', 'search', 'execute'] }), 'reject'),
});
```

</TabItem>
<TabItem label="Python">

```python
import re

from deft_subspace.acp import allow, allow_inside, ask_in_terminal, first_of, read_only, reject, start

await start("claude", on_permission=read_only)  # reads and searches yes, the rest no
await start("claude", on_permission=first_of(allow_inside(repo), ask_in_terminal()))  # edits inside the repo yes, ask about the rest
await start(
    "claude",
    on_permission=first_of(reject(commands=re.compile(r"rm -rf|git push")), allow(kinds=["read", "search", "execute"]), "reject"),
)
```

</TabItem>
</Tabs>

- A rule returns a decision, or nothing ("no opinion"). `firstOf(...)` tries them in order; a fixed answer (`'allow'`, `'reject'`) can end the list, and with no decision at all it rejects.
- `allow(match)` and `reject(match)` match on tool `kinds`, `titles`, `commands` (a string to look for, or a regular expression) and `inside` (every path the request touches is inside a folder). The paths come from the tool call's locations and the usual input fields; `..` cannot leave the folder.
- `allowInside(root)` is `allow({ inside: root })`; `readOnly` allows the read kinds (`read`, `search`, `fetch`, `think`).
- `askInTerminal()` asks y / n / always (always: for that kind of tool, while the handler lives). With no terminal to ask on, it rejects.
- `onPermission` also takes a fixed answer: `onPermission: 'reject'`.

## Answers

A fixed answer, or a function returning one of:

- `'allow'` and `'reject'`: the agent's once-only option of that kind (or its always option, if that is all it offers).
- `'allow_always'` and `'reject_always'`: prefer the always option.
- `{ optionId }`: exactly that option.
- `'cancelled'`.

## Failing closed

- A handler that throws, or returns an option the agent did not offer, is a rejection.
- The handler's `signal` fires if the turn is cancelled while you decide. The question is then answered `cancelled`, as the spec requires.
- A question that arrives when no turn is running is answered `cancelled`. The exception is a question about listed [background work](../../background/background-work/), which your handler answers.

## What a request holds

`request.title`, `request.toolCall` (the tool call as it stands, with this request's fields merged in), `request.command` (v2 command permissions: `command` and `cwd`), `request.options`, `request.protocol`, and `request.raw`.
