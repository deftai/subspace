`@deft-subspace/acp-testkit` tests ACP agents and clients, written with Subspace or not. Everything uses one trace format: JSON Lines, a header and then `{ t, dir, msg }` records. Traces are language-neutral, so any implementation can replay them.

## Record and replay

- `recordAgent(command, options)` (from `./node`) runs a real agent and records the connection. `recorder()` gives a `tap` for any peer or client, and `tapChannel()` records any channel. `replaceStrings()` and `redactKeys()` keep paths and identities out of traces.
- `replayAgent(channel, trace)` plays the agent's side back to a live client. It remaps ids, matches the client's calls by method in order, tolerates different params, and rejects `done` with a `ReplayDivergence` (expected vs got) instead of hanging.

## Faults

`faultChannel(channel, { read, write })` adds `delay`, `disconnectAfter`, `closeWhen(isUpdate(...))`, and for bytes `rechunk`, `merge`, `coalesce` and `injectLines` (banner lines and other noise real agents print).

## Conformance

- `checkAgent(channel, options)` drives any agent and reports each check; `checkAgentProcess(command, options)` starts a program and checks it. `waive: { checkId: reason }` turns a known failure into `WAIVE`; An agent's quirks carry its waivers (`resolveAgent(catalog, name).waivers`; see [agents files](/subspace/client/agents-file/)), which `subspace check <agent>` applies (`--strict` to not).
- `checkClient(connect)` plays an agent against any client; `acpClientDriver()` connects ours.
- From the command line: `node --conditions=subspace-source packages/acp-testkit/scripts/check-agent.ts <agent command>`, with `ONLY` to pick checks and `MODE` to switch each session to a mode first.

The checks are listed on [Conformance](../../behaviour/conformance/).

## Scenarios

Describe what an agent should do, and check it did:

```json
{
  "name": "writes a greeting",
  "agent": "claude",
  "workspace": { "from": "fixtures/empty" },
  "permissions": { "allow": ["read", "edit"] },
  "turns": [
    {
      "prompt": "Create hello.txt containing hi",
      "expect": {
        "end": "completed",
        "files": { "hello.txt": { "contains": "hi" } },
        "toolCalls": { "min": 1, "kinds": ["edit"], "allCompleted": true },
        "permissions": { "min": 1 }
      }
    }
  ],
  "snapshot": "snapshots/greeting.json"
}
```

Run with `subspace test greeting.scenario.json` (several files, a list, or `{ "scenarios": [...] }`; also TypeScript modules exporting `defineScenario(...)`), or `runScenario()` from `@deft-subspace/acp-testkit/node`.

- **Agent:** a known name or `{ command, args, env, mode }`; it starts in its ask-first mode unless `mode` says otherwise.
- **Workspace:** a fresh temporary folder each run, empty or a copy of `workspace.from` (relative to the scenario file).
- **Permissions:** `allow`, `reject` (the default), `read-only`, or `{ allow: [kinds], reject: [kinds] }`.
- **Expectations, per turn:** `end` (`completed`, `refused`, `cancelled`, `limit`, `error`), `stopReason`, `text` (`contains`, `notContains`, `matches`), `toolCalls` (`min`, `max`, `titles`, `kinds`, `allCompleted`), `permissions` (`min`, `max`, `titles`), `files` (`exists`, `contains`, `equals`, `matches`), `updates` (`min`, `max`).
- **Snapshots:** `snapshot` records each turn's outcome (how it ended, its text and its tool calls) the first time and compares later runs with it; `--update` accepts a change. Best for deterministic agents (your own, or replayed ones). A snapshot that is not valid JSON fails and is left as it is. In CI (`--ci`, `requireSnapshots`, on when the `CI` environment variable is set) a missing snapshot fails instead of being written: commit them.
- **When it fails:** a failure bundle with the trace, the report and the workspace's file list, in its own folder (`--artifacts <dir>`, default under the temp folder). A passing scenario removes its workspace and trace (`--keep`, `keep: true` to keep them).
- **For CI:** `--junit results.xml` (a test case per turn), `--json`, and exit code 1 when any scenario failed.

## The quirks corpus

`packages/acp-testkit/corpus/` holds traces recorded from Grok Build and the Claude and Codex adapters: a plain turn, a cancel mid-stream, and a refused write, for each. The test suite replays them to the client and checks it gets the result recorded live. What they show is on [Quirks](../../behaviour/quirks/).
