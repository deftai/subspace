A client can give each session [MCP](https://modelcontextprotocol.io) servers for the agent to use: a program it starts (`stdio`), a URL it connects to (`http`, or `sse` on v1), or tools the client serves itself (`acp`, see [MCP-over-ACP](../over-acp/)).

<Example file="mcp-servers.ts" ts={servers} />

- Each server is written in the agent's protocol: v1 stdio has no `type` and needs `args` and `env`; v2 stdio needs an absolute command.
- `client.supports.mcp` says which transports the agent takes. A server of another transport throws a `CapabilityError` before `session/new` is sent. v1 agents always take stdio; v2 agents say so.
- `env` and `headers` are plain objects here, and name/value lists on the wire.

## On the agent side

`serveAgent` gives your session hooks the servers typed (`servers`), and each turn `turn.mcpServers`. Advertise what you take with `mcpTransports`. For `stdio`, `http` and `sse` the agent connects itself, with any MCP client; for `acp`, use `turn.mcp(name)`.
